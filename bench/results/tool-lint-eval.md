# Tool description lint: false positives and recall

Generated by `bench/tool_lint_eval.py` from `bench/data/tool_descriptions_benign.jsonl` (159 strings from 7 MCP reference servers, modelcontextprotocol/servers@194cc86e3ae6) and `bench/data/tool_descriptions_poisoned.jsonl` (32 labelled synthetic strings). No server was run: the benign strings were read from source by `bench/tool_corpus.py`.

> **Caveats.** The poisoned set was written by the same person who wrote the lint, after reading the same attack write-ups, so the explicit and hidden categories flatter it. The subtle category exists to show what it misses. The benign side is seven servers, mostly short descriptions; large third-party servers with long, link-heavy descriptions will trip the `url` and `long` flags more often. Every number here moves when the data does.

## Result

- **Benign tool descriptions flagged: 1 of 63 (2%).** In `auto_first` these tools would wait as pending instead of being served. Servers affected: sequentialthinking.
- Benign strings flagged overall (parameters and fields included): 1 of 159 (1%).
- **Poisoned strings flagged: 19 of 32 (59%).**

| poisoned category | flagged | what it is |
|---|---|---|
| explicit | 8/8 | instruction blocks in plain sight (`<IMPORTANT>`, "ignore previous") |
| hidden | 5/5 | zero-width, tag-block or bidi characters, or the payload pushed out of view |
| shadowing | 2/5 | instructions about another server's tool |
| param | 4/5 | the payload in a parameter description |
| subtle | 0/9 | innocent wording: no keyword, path or URL |

Tools per reference server: everything 24, fetch 1, filesystem 14, git 12, memory 9, sequentialthinking 1, time 2.
