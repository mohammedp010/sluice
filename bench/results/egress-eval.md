# Secret egress guard: recall, false positives, speed

Generated by `bench/egress_eval.py`. Positives: 560 fake secrets made at run time (14 formats, each in several surrounding texts); none is stored. Negatives: 4,399 KB of real text from this repository (426 documents: source, docs, UI code, policies, the git log), plus random UUIDs and sha256 digests and six screenshots as base64.

> **Caveats.** The positives come from the same format rules the detector uses, so known-format recall measures that the rules are wired up, not that they cover every real key format. The evasion rows are the honest part: an encoded, split or spaced secret gets through. The negatives are one repository's text; logs and data from other systems will differ.

## Result

The first run found two detector bugs, both fixed before this one: `=` was allowed anywhere in a random run, so `PASSWORD=<secret>` swallowed its own hint (high_entropy 28/40), and the hint was looked for across line breaks, so three git SHAs counted as secrets because the commit subject above them said "Keys" (3 false positives). `tests/test_egress_guard.py` has a regression test for each. The detector has no tuned threshold; nothing else changed.

- **Found 560 of 560 fake secrets (100%).**
- **False positives: 0 in 4,399 KB of real text.**
- Speed: **129.2 µs per KB** (one core, `time.perf_counter`).
